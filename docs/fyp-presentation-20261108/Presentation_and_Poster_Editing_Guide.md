# Presentation and poster editing guide

## Timing and structure

The lecturer has not confirmed the presentation limit. This is a ten-minute draft including a two-minute demo; Q&A has no assumed allocation. The 14-slide deck uses problem → objectives → client-led solution → mechanism → connected feature journeys → testing → conclusion → demo → questions. The demo is the final content section. It is not necessary to keep a hackathon’s two-feature limit, but do not spend the FYP talk listing every setting. Explain the evidence and the reason for the main functions.

The added FYP content is the objectives, development approach, testing and evaluation—not simply a larger product pitch. A business plan is not assumed required. For 15 minutes, expand the method, data model and genuine evaluation discussion; do not stretch the same narration. For five minutes, use problem (35 s), solution/objectives (35 s), mechanism (35 s), two connected feature stories (45 s), evidence/limit (30 s), and a 120-second demo. Ask the lecturer about Q&A separately.

Neither is automatically “better” for every purpose.

## Replace evaluation wording before final submission

The current “formal client and student evaluation is planned” wording reflects the evidence available when the poster was made. It is not intended to remain after results have been collected. Replace it with the actual participants, tasks, main findings and any resulting change. Functional pass results and survey findings are different kinds of evidence. Do not invent a positive rating, participant count or conversion effect.

Poster font settings (A1 at its original 594 × 841 mm):

| Element | Font | Size | Style / colour |
| --- | --- | --- | --- |
| Existing evaluation “planned” text | Arial | 22 pt | Bold, #173F32 |
| Replacement short result summary | Arial | 22 pt | Regular, #23362D; use #173F32 bold only for a short emphasis |
| Conclusion & next step heading | Arial | 27 pt | Bold, #173F32 |
| Testing & results heading | Arial | 28 pt | Bold, #173F32 |
| Normal poster paragraph | Arial | 22–23 pt | Regular, #23362D |
| Original objective text | Arial | 22.5 pt | Regular, #23362D |

For Canva, keep the A1 dimensions when importing. Font numbers may change if the whole page is rescaled. Use Arial if available; otherwise use one consistent close sans-serif and recheck line breaks. Do not shrink body text to squeeze in a long survey paragraph. The current evaluation box has room for a short two-to-three-line summary; use a concise truthful finding or redistribute the section if more evidence is required. A possible structure is “Client: [actual finding]. Students: [n], [actual finding].” These brackets are author fields, not results.

Slide 11 is also a development-results draft. Update it with genuine evaluation findings before the final presentation. Keep a brief explanation of the software checks and their local-test limits. Timing targets include pauses and pointing to screens; the script is not meant to be rushed line by line.
